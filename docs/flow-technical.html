The whole journey at a glance

AFive phases, one downloaded file

A request moves through five phases. The interesting behaviour lives in Extract (turning a PDF's glyph soup back into paragraphs) and Render (putting translated — usually longer — text back without breaking the layout). Translation itself is the easy part; most of the code exists to protect what must not be translated and to make the result fit.

One endpoint, three pipelines. POST /translate/document routes purely by file extension: PDFs take the direct PyMuPDF pipeline, .txt/.docx/.pptx take native segment translation, and legacy .doc/.ppt are converted by LibreOffice first. The legacy /translate/pdf and /translate/pdf/advanced routes are hidden compatibility/internal routes — don't build on them.

Intake

BEntry & routing — which pipeline runs?

Validation happens before anything touches the file; content policy happens before anything is translated. All checks fail with an explicit 400 rather than a half-translated document.

start / end step decision rejected

Validation lives in document_translate_service.validate_document_request; the formula-policy gate is pdf_content_policy.ensure_pdf_translation_allowed. The public endpoint always uses the direct layout engine with image-text translation off; only the hidden /translate/pdf/advanced route can select the HTML engine or experiments.

extension

Must be one of .pdf .txt .doc .docx .ppt .pptx. Structured formats (.json .csv .xlsx) are deliberately rejected — see "Structured Files Guidance" in the README.

target_lang

Required; a two-letter code from the 24 EU languages (app/core/languages.py). Regional forms like pt-br are normalized to pt.

source_lang

Optional. When given, it must differ from target_lang. When absent, detection runs later — and only then.

engine

llm · deepl · adaptive; empty falls back to the TRANSLATION_ENGINE env default (llm). deepl + Maltese/Irish target fails fast with a clear 400.

The production path

CThe direct PDF pipeline, stage by stage

PDFs have no paragraphs — only positioned glyph runs. The direct engine reconstructs the document's structure, translates it, then surgically swaps the text while leaving images, vector art, and layout untouched.

1

Content-policy gate

pdf_content_policy.py

Every page's text lines are scored for math symbols (= ∑ ∫ √ ≤ ≈ …), trailing equation numbers like (3.1), and math functions (sin( log( argmax_ …). Formula-heavy documents are rejected with HTTP 400 before any model call — translating equations garbles them.

reject: density
≥ 12 formula lines and ≥ 8% of all lines
reject: spread
≥ 3 pages, ≥ 8 formula lines, on ≥ 25% of pages
reject: dense page
≥ 12 formula lines total and ≥ 8 on one page
2

Block extraction & line merging

extract_native_blocks.py

PyMuPDF yields per-line boxes with font, size, colour, and rotation. Consecutive lines are merged back into paragraphs only when the geometry and typography agree: same raw block and font, size delta ≤ max(0.75pt, 8%), a plausible vertical gap (up to ~half a line of overlap is tolerated — line boxes span ascender to descender), aligned left edges, and ≥ 35% horizontal overlap. Merges are refused across sentence boundaries with extra leading, label lines ending in ":", table-ish rows, reference lines, headers/footers, and bullet starts.

multi-column detection
≥ 16 lines, ≥ 12 narrow, ≥ 5 per half, avg width ≤ 42% of page → two columns
reading order
full-width top → left column → right column → full-width middle → bottom
rotation
line dir vector → 0/90/180/270; rotated text keeps its exact box
alignment
centered detected from shared midpoints across ≥ 2 lines; single-line captions default to center
3

Scholarly block classification

extract_native_blocks.py

Each merged block gets a kind that later controls how much its box may grow: title, abstract, keywords, caption, table, reference, bullet, label, paragraph, or line. Once a standalone "References"/"Bibliography" heading appears in the document's latter half, everything after it is marked reference — bibliographies are canonical citations and are never translated.

4

Source-language detection (only if needed)

translator_llm.py · extract_native_blocks.py

Runs only when source_lang was not supplied. PDF metadata language wins if it maps to an EU code. Otherwise text samples are cleaned (≥ 24 chars, ≥ 12 letters, no URLs/emails, not digit-heavy), aggregated into ~320-character clumps (max 10), and the text model returns an ISO 639-1 code — falling back to en. The DeepL backend instead reads detected_source_lang from a probe call. If the detected source equals the target, the run errors out rather than "translating" a document into itself.

5

Protect what must survive verbatim

protected_text.py

Emails, URLs, and @handles are swapped for opaque tokens (ZXQNT0QXZ, ZXQNT1QXZ, …) before translation and restored after, so no model can "translate" a domain name. Blocks with nothing translatable left (< 2 letters beside tokens), contact-identity blocks (a protected token plus a few capitalized name words), and reference blocks are skipped entirely — their source text stays on the page untouched.

6

Per-block translation with a suspicion loop

translate_pdf_direct.py · translator_llm.py

Each block is translated one at a time with a strict single-snippet prompt (temperature 0). Output is checked for source-text leakage, degeneration loops, and lost protection tokens; a suspicious result earns exactly one retry, and a still-suspicious retry is rejected — the source text is kept rather than shipping a bad translation. The full loop is drawn in section D.

7

Placement planning — will it fit?

translate_pdf_direct.py · fonts.py

Translations are usually longer than their source. For each block a side-effect-free planner picks a box: the source box, grown by kind-specific factors (paragraphs may grow more than captions), clamped so it can never spill into the block below, optionally widened sideways into genuinely free space for short lines. It then searches candidate boxes × line-heights (base, 1.0, 0.94) × font sizes (shrinking ×0.92 down to 7pt; display text starts at ≥ 8pt) until the text truly fits — insert_textbox silently renders nothing on overflow, so only a non-negative spare is accepted. No fit → the block is unplaced and its source text is preserved.

glyph-aware fonts
any char > U+00FF (Greek, Latin-Extended, Cyrillic…) switches to a Noto/DejaVu Unicode fallback with per-glyph coverage checks
centered blocks
widened symmetrically so the midpoint — and the centered text — stays put
rotated text
keeps exact source box and orientation; only the font shrinks
8

Two-phase redaction & write-back

translate_pdf_direct.py

Source glyphs are removed with text-only redactions (images and line art untouched). Critically, this is done in two phases per page: all redactions are queued and applied first, and only then is all translated text inserted. Redaction boxes are trimmed away from "preserved" rects — skipped/rejected/unplaced blocks and number-only lines that were never translated — so a neighbour's redaction can't erase text that must survive.

Why two-phase? Adjacent line boxes overlap by a few points. In a naive redact-then-write-per-block loop, block N+1's redaction erases part of the text just written for block N, silently blanking output. Planning everything first and batching redactions per page makes that impossible.

9

Finalize & deliver

translate_pdf_direct.py

Link annotations captured before rewriting are restored (deduplicated by geometry + target — redaction drops them otherwise). The document is saved with garbage=3, deflate=True, translation stats are reported (translated / retried / rejected / unplaced counts, API calls), and the API streams the file back while a background task deletes the temp directory.

Translate

DThe per-block translation loop

Every block is either skipped (source kept by design), translated cleanly, or rejected after one retry (source kept for safety). Nothing is ever silently dropped — the failure mode is always "original text remains", never "text disappears".

start / end step decision rejected (source kept)

The dashed orange rail is the per-block loop: skipped, rejected, and stored blocks all return for the next one. "Suspicious" means any of: identical to the source, a long exact overlap with it, a degenerate repetition loop, English stopword leakage into a non-English target, or a mangled protection token. Retries fire only for blocks longer than 16 characters; token loss forces a retry unconditionally.

Translate

EThree translation backends, one contract

The engine field / --engine flag selects who translates the text. All three implement the same four methods (detect_language, translate_single_strict, translate_strings_batch, translate_nodes), so the pipelines never care which one is running (translator_factory.py).

llm · default

OpenAI-compatible endpoint (vLLM, often RunPod). Batch JSON prompts for segments/nodes; strict single-snippet prompt for the retry path. JSON responses are fence-unwrapped with a regex partial-recovery fallback.

all 24 languagestemp 0.1 / 0.0 strictbatch 50

deepl

DeepL only. Errors (quota, rate limit, auth) are surfaced, never hidden. English and Portuguese targets need regional variants — DEEPL_EN_VARIANT / DEEPL_PT_VARIANT, defaulting to EN-GB / PT-PT.

no Maltese (mt)no Irish (ga)hard 400 for those targets

adaptive

DeepL first, LLM on any DeepL error. An unsupported language falls back per-call only; a genuine service failure sets a sticky "DeepL down" flag so the rest of the run goes straight to the LLM instead of hammering an exhausted quota.

all 24 languagessticky failoverlazy LLM init
adaptive · mt/ga target

UnsupportedDeepLLanguageError → this call goes to the LLM; DeepL stays enabled for everything else.

adaptive · quota/rate/auth

Any deepl.DeepLException/connection error → call falls back and _deepl_down sticks for the rest of the document.

every engine

The suspicion checks and retry loop in section D run identically regardless of backend — DeepL output is verified too.

The backend only controls the text-translation step. Text embedded in images is always OCR'd by the vision LLM (DeepL cannot OCR); the translate-after-OCR step then honours the selected engine. Source-language detection also routes through the selected backend.

Extract · Translate · Render

FNative formats: txt, docx, pptx (and legacy doc/ppt)

Non-PDF formats keep their native container — the file that comes back is the same format that went in, with only human-readable text replaced. All three share translate_text_segments.py: batch translation (≤ 40 segments per call), source detection when needed, and the same per-segment retry guard as the PDF path.

.txt

translate_txt.py
  1. Decode bytes trying utf-8 → utf-8-sig → cp1252 → latin-1.
  2. Split into segments on blank lines, keeping the blank lines as segments.
  3. Translate non-empty segments in batches; blank segments pass through untouched.
  4. Rejoin in order → paragraph structure and spacing survive exactly.

.docx

translate_docx.py
  1. Open the OOXML zip; parse document.xml, footnotes, endnotes, comments, headers, footers.
  2. Per paragraph, collect its w:t runs and join them into one string.
  3. Translate the joined text; write it into the first run, blank the rest (per-run styling of later runs is traded for translation coherence).
  4. Rebuild the zip byte-for-byte except the touched XML parts — styles, images, tables intact.

.pptx

translate_pptx.py
  1. Same zip surgery over ppt/slides/slide*.xml and notesSlides/.
  2. Per a:p paragraph, join its a:t runs, translate, first-run write-back.
  3. Layouts, masters, media, and animations are copied through unchanged.

.doc / .ppt (legacy)

convert_legacy_office.py
  1. soffice --headless --convert-to docx|pptx (LibreOffice required; clear error if missing).
  2. The converted file then takes the normal .docx/.pptx lane.
  3. Output keeps the modern extension — a .doc upload returns a .docx.

Advanced / fallback

GThe HTML engine and image-embedded text

Two capabilities live behind the hidden /translate/pdf/advanced route (and CLI flags). Neither is part of the public contract.

html layout engine

convert_pdf_to_html.py · translator_llm.py · render_html_to_pdf.py
  1. Read the first page's size (pdf_page_size.py) so the output matches.
  2. Poppler pdftohtml -c -s -noframes → one position-preserving HTML file.
  3. Either translate every text node (BeautifulSoup NavigableString walk, whitespace preserved around each node) or apply an exact-match JSON replacement mapping (replace_html_text.py) — mutually exclusive with target_lang.
  4. Render back to PDF with Playwright Chromium (auto-installed on first use); when text changed, overflow adjustment and background-image hiding are enabled.

image-text translation (experimental)

translate_pdf_image_text.py · vision_llm.py
  1. For each embedded image ≥ 80×50 pt, render a 2× crop.
  2. The vision LLM returns figure-embedded text blocks as JSON with bounding boxes normalized 0–1000 (body text is explicitly excluded from the prompt).
  3. Up to 20 blocks per region are translated by the selected backend, with the same retry guard.
  4. Each block's rect is white-filled and the translation overlaid, shrinking the font up to 6× (×0.92) to fit.

Off by default for a reason. Overlaying text on raster images is destructive to the image region and OCR boxes are approximate — the public endpoint always runs with translate_image_text=False. Enable it only via the advanced route/CLI when the document's figures carry essential text.

IFailure modes

What a caller can see and why. The design principle throughout: fail loudly before translating, and when a single block fails mid-run, keep its source text rather than drop content.

StatusTriggerNotes
401Missing/wrong basic authApplies to every route, including /docs and /openapi.json.
400Unsupported extensionAnything outside .pdf .txt .doc .docx .ppt .pptx — including the deliberately rejected structured formats.
400Missing/invalid target_langMust be one of the 24 EU codes; the error lists them.
400source_lang == target_langOnly when both are supplied explicitly.
400Invalid engineAnything other than llm / deepl / adaptive (or empty).
400deepl engine + mt/ga targetFast fail with a pointer to llm/adaptive; adaptive silently falls back instead.
400Formula-heavy PDFPdfContentPolicyError, raised before any model call.
500Pipeline failureWrapped as "Translation pipeline failed: …". Includes: detected source equals target, no translatable text found in the PDF, LibreOffice missing for .doc/.ppt, and DeepL service errors in deepl mode.

Inside a run, failure is graceful. A block whose translation is rejected or cannot be placed keeps its source text on the page (counted in blocks_rejected / blocks_unplaced); a partially DeepL-failed adaptive run continues on the LLM. The only mid-run hard stop is the LLM API being unreachable.
